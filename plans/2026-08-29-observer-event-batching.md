# Observer Event Batching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use test-driven development and verification-before-completion for every task.

**Goal:** Replace one observer-model request per tool event with bounded per-session batches that flush after 10 quiet seconds, 30 total seconds, 10 events, or a safe payload-size limit.

**Architecture:** Add a small in-memory `ObservationBatcher` before `SessionMessageBuffer`. HTTP hooks still return immediately. A batch becomes one synthetic `BatchedToolUse` observation, so all existing Claude, Gemini, OpenRouter, XML parsing, storage, privacy, and secret-handling paths remain unchanged.

**Tech Stack:** TypeScript, Bun tests, existing Claude Mem worker and prompt builder.

## Global Constraints

- Keep batches isolated by session and agent identity.
- Flush after 10 seconds without a new event.
- Flush after 30 seconds even during continuous activity.
- Flush at 10 events or before either serialized input/output side exceeds 14,000 characters.
- Preserve a single event without changing its shape.
- Flush pending observations before a session summary.
- Do not add another service, relay, database queue, or model call.
